## 1. Постановка задачи

Нужно разработать доменную модель и консольное приложение модуля «ПОС» для учёта преподавательской оценки студентов. В приложении есть студенты, критерии с максимумом и весом, оценки и итог по студенту. Используются DDD, слоёная архитектура Ports and Adapters и паттерны GoF.

Правила, которые модель не даёт нарушить:

- балл не выходит за пределы критерия
- оценку можно выставить только по критерию из рубрикатора
- итог согласован с текущим набором оценок и считается в Domain Service


## 2. Что сделано самостоятельно

Изучил ТЗ
Выписал язык предметной области (студент, критерий, оценка, итог), инварианты и обязательные сценарии

Спроектировал доменную модель
Решил, что `Student`, `Criterion` и `Evaluation` — сущности, а `Score` — Value Object, который нельзя создать вне диапазона. Корнем агрегата сделал `Rubric`: она владеет критериями. `Evaluation` ссылается на студента и критерий по id, поэтому не вырастает в один большой агрегат

Выбрал архитектуру
Ports and Adapters: в центре `include/domain`, снаружи `src`. Порты репозиториев объявлены в домене, реализации лежат в `src`. Зависимости направлены внутрь, граф собирается в одном месте (`src/container.go`)

Выбрал паттерны
- Фабрика (`EvaluationFactory`) — единственная точка создания оценки с проверкой критерия и диапазона
- Декоратор (`RoundedStrategy`) — округление поверх любой стратегии подсчёта
- Фасад (`Facade`) — единая точка сценариев для консоли
- Стратегия (`ScoringStrategy`) — сменяемое правило итога, сейчас `WeightedAll` и `WeightedRatedOnly`

Продумал интерфейс

## 4. Сценарий работы программы

1. Запуск: `main` вызывает `buildFacade`, который создаёт репозитории, калькулятор со стратегией и фасад
2. Пользователь добавляет студентов и критерии через меню
3. При выставлении оценки фасад находит студента, проверяет, что оценки ещё нет, и вызывает фабрику. Фабрика проверяет критерий и диапазон и возвращает `Evaluation`, которая сохраняется в репозитории
4. Исправление идёт через `Evaluation.Rescore`, отмена — через удаление из репозитория
5. Итог считает `ScoreCalculator` по рубрикатору и оценкам студента
6. Экспорт записывает файл CSV со столбцами `student_id`, `name`, `total_percent`

## 7. Инварианты и их выполнение

Балл не выходит за пределы критерия
`NewScore` возвращает `ErrScoreOutOfRange`, создать `Score` вне диапазона нельзя. `Rescore` использует тот же конструктор

Оценка только по критерию из рубрикатора
`EvaluationFactory.Create` ищет критерий в `Rubric` и возвращает `ErrCriterionNotInRubric`

Итог согласован с оценками
Итог не хранится, а каждый раз считается в `ScoreCalculator` из текущих оценок

Критерий и студент корректны
`NewCriterion` отклоняет пустое название, `max_score <= 0` и `вес <= 0`, `NewStudent` отклоняет пустое имя

Одна оценка на пару студент + критерий
`SetGrade` возвращает `ErrDuplicateEvaluation`, если оценка уже есть
